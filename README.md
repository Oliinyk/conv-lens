# Conv Lens

Самохостна діагностика конверсії для будь-якого сайту: фунел, фрикшн, запис сесій,
карта кліків і готові діагнози «де саме втрачаються замовлення».

Відповідає не на питання «скільки людей пішло» (це показує будь-яка аналітика), а на
питання **«де саме вони спіткнулись і скільки це коштувало»**.

Встановлення — один рядок на сайті. Інструкція для власника сайту без технічних
знань: **[INSTALL.md](INSTALL.md)**.

```html
<script src="https://lens.example.com/cl/t.js?s=SITEKEY" defer></script>
```

## Що воно збирає

| | |
|---|---|
| **Фрикшн** | rage-кліки, мертві кліки, JS-помилки, невдалі запити, помилки валідації, підвисання інтерфейсу, зум, горизонтальний скрол, метання по сторінці, намір піти |
| **Фунел** | кроки з пресету платформи або власні; реальні переходи, а не лише перегляди |
| **Джерела** | канали (пошук, реклама, соцмережі, прямі), конкретні джерела, utm-кампанії, сайти-донори і сторінки входу — кожне з конверсією, доходом і фрикшном |
| **Форми** | де саме обриваються, скільки часу в полі, скільки переписують, які помилки |
| **Запис сесій** | відтворення по знімку верстки — працює, навіть коли Conv Lens на іншому домені |
| **Карта кліків** | кліки, привʼязані до елементів, тому не розʼїжджаються при іншій ширині екрана |
| **Швидкість** | LCP, CLS, INP, TTFB у звʼязці з конверсією |
| **Сегменти** | чим ті, хто не купив, відрізняються від тих, хто купив |
| **Опитування** | питання на виході тим, хто збирається піти |

Усе це зводиться у вкладку **Діагнози**: список проблем, відсортований за оцінкою
втрачених замовлень і грошей, з посиланнями на конкретні записи сесій.

## Платформонезалежність

Conv Lens нічого не знає про вашу CMS і нічого в ній не потребує.

* **Кроки фунела ловляться без коду на сайті** — через пресети платформ
  (WooCommerce, Shopify, OpenCart/Horoshop, довільний магазин, лендінг із заявками).
  Натискання «Додати в кошик» розпізнається за селектором або текстом кнопки,
  покупка — за переходом на сторінку подяки.
* **Селектори стійкі до utility-класів.** Для сайтів на Tailwind і подібних селектор
  будується з `id`, `data-testid`, `aria-label` або тексту кнопки, а класи-утиліти
  (`px-4`, `flex`, `text-sm`) відкидаються.
* **Запис сесій не потребує доступу до сайту.** Трекер зберігає «скелет» верстки, і
  плеєр відтворює сторінку з нього. Коли Conv Lens стоїть на тому ж домені, що й сайт,
  автоматично вмикається точніший режим із реальною сторінкою в iframe.
* **Один інстанс — багато сайтів.** У кожного свій ключ, свій фунел і свої дані.

## Запуск

Потрібен Node.js 22+. Залежностей для локального запуску немає — база через
вбудований `node:sqlite`.

```bash
node bin/conv-lens.js serve           # дашборд + колектор
node bin/conv-lens.js seed            # демо-дані, щоб побачити дашборд наповненим
node bin/conv-lens.js report          # текстовий діагноз у термінал
node bin/conv-lens.js sites           # сайти, ключі і коди для вставки
node bin/conv-lens.js add --origin https://shop.com --preset woocommerce
node bin/conv-lens.js key --set MY_KEY
node bin/conv-lens.js purge --days 30
```

Корисні прапорці: `--port`, `--host`, `--db <шлях|libsql://…>`, `--site <id>`.

### Dry run: перевірити фунел до встановлення

```bash
node bin/conv-lens.js serve --preview https://shop.com
```

Відкрийте `/live` — Conv Lens проксіює чужий сайт через себе з доданим трекером.
Видно, чи правильно ловляться кроки, ще до того, як щось ставити на сайт.

## Деплой

### Vercel

Форк → Add New Project → **Storage → Create Database → Turso** → Deploy.
`vercel.json` уже налаштований: `/cl/t.js` і `/cl/collect` ведуть у функцію,
корінь віддає дашборд, усе закрито від індексації.

Змінні оточення:

| Змінна | Навіщо |
|---|---|
| `CONV_LENS_TOKEN` | ключ дашборда; якщо заданий, має пріоритет над ключем у базі |
| `CONV_LENS_SALT` | сіль для хешування IP; задайте свою |
| `CONV_LENS_DB_URL` / `CONV_LENS_DB_TOKEN` | база, якщо не користуєтесь інтеграцією Vercel |
| `CONV_LENS_PUBLIC_URL` | публічна адреса, якщо вона відрізняється від домену Vercel |

Підключення до бази шукається і за стандартними іменами інтеграцій
(`TURSO_DATABASE_URL`, `*_AUTH_TOKEN` тощо), тому зазвичай нічого вписувати не треба.

### Свій сервер

```bash
node bin/conv-lens.js serve --host 0.0.0.0 --port 8777
```

і nginx з HTTPS попереду. База — файл `./data/conv-lens.db`.

## Як влаштовано

```
tracker/conv-lens.js     трекер у браузері; без залежностей, ES5
src/router.js            весь роутинг; не знає, в якому середовищі працює
server/node.js           рантайм node:http + статика + dry-run проксі
api/[...route].js        рантайм Vercel; тільки перекладає запит у виклик роутера
src/db.js                сховище: node:sqlite або libSQL/Turso, один async-інтерфейс
src/ingest.js            батч подій → рядки; рахує фрикшн і крок фунела
src/aggregate.js         усі запити дашборда; кожен скоупиться по сайту
src/insights.js          діагнози з оцінкою втрат
src/presets.js           готові фунели під платформи
dashboard/               дашборд; без збірки, нативні ES-модулі
integrations/wordpress/  плагін WP: адреса + ключ, далі події WooCommerce
```

Один і той самий код обслуговує локальний сервер і serverless: рантайми лише
перекладають запит у `handle()` і віддають результат.

Схема бази одна для обох сховищ, діалект SQLite. Кожен рядок у `sessions`, `events`
і `snapshots` несе `site_id`, і `buildFilter` додає його в кожен запит — дані сайтів
не перетинаються навіть помилково.

## Безпека і приватність

* Дашборд закритий ключем. Поки інстанс порожній, він відкритий — рівно щоб пройти
  майстер налаштування; щойно зʼявляється перший сайт, ключ стає обовʼязковим.
* Ключ сайту публічний за природою (він у коді сторінки), тому колектор **не**
  обмежує CORS: інакше домен, записаний із дрібною помилкою, мовчки вимкнув би
  збір даних, а захисту це не дає. Захищений саме дашборд.
* Поля з паролями не читаються ніколи.
* IP пишеться разом із хешем на щоденній солі (`CONV_LENS_SALT`).
* Do Not Track поважається за замовчуванням.
* Дані старші за `retentionDays` (типово 30) видаляються самі, разом з подіями
  і знімками.
